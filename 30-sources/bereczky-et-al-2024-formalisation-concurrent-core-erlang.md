# A Formalisation of Core Erlang, a Concurrent Actor Language

## Reference

Péter Bereczky, Dániel Horpácsi, and Simon Thompson. “A Formalisation of Core
Erlang, a Concurrent Actor Language.” *Acta Cybernetica* 26, no. 3 (2024):
373–404. [doi:10.14232/actacyb.298977](https://doi.org/10.14232/actacyb.298977).
[Open manuscript](https://arxiv.org/abs/2311.10482)

## Contribution

The authors give a proof-assistant formalisation of a concurrent subset of Core
Erlang. The development covers local expression semantics, processes,
asynchronous communication, and a labelled transition system. It proves
properties including determinism or confluence in the relevant semantic
layers and develops behavioural equivalence through bisimulation.

## Finding

Concurrent Core Erlang can be given a machine-checked operational semantics in
which process behaviour is compared observationally rather than by requiring
identical internal reduction sequences. That matters for a concurrent agent
runtime: scheduler interleavings and generated process identifiers make
literal execution equality the wrong equivalence.

## Relevance

The formalisation provides a model for connecting an agent language's small IR
to BEAM-like actor semantics. Bisimulation and trace observations are better
foundations for concurrency-sensitive law tests than comparing raw mailboxes or
execution traces byte for byte.

It also suggests a two-level validation strategy: prove laws for a deliberately
small semantic core, then property-test the compiler and runtime against those
observations.

## Limits

The formalised language is a subset and an academic semantics, not the complete
OTP compiler or ERTS implementation. It does not establish that arbitrary Core
Erlang generated by a third-party compiler is safe, nor does it cover agent
effects such as model calls, durable stores, deadlines, or compensation.
