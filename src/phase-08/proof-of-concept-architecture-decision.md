# A-Lang Proof-of-Concept Architecture Decision

## Decision

Revise the combined architecture and authorize exactly one more bounded
prototype. Retain BEAM as the compiler/runtime substrate, the runtime-local
capability broker as the effect reference monitor, and explicit durability for
consequential effects. Retain categorical structure only as internal laws and
analyses. Narrow the task-language claim to machine-checkable executable
contracts; the proof of concept does not establish that LLMs understand tasks
better or that the current syntax helps authors.

This is not production approval. The machine-readable decision generated by
`make decide` records six layer dispositions:

- task language — `narrow`;
- categorical IR — `narrow`;
- BEAM compiler and runtime — `promote` to the next prototype;
- local capability broker — `promote` for runtime-local enforcement;
- explicit durability — `promote` for consequential effects; and
- combined architecture — `revise`.

The [falsification review](falsification-review.md) explains the positive and
negative evidence for each outcome.

## Accepted claims

On the pinned OTP 29 environment, the trusted source-to-artifact toolchain and
generated programs execute on ERTS; compiled observations agree with bounded
oracles for the accepted subset; the broker materially enforces local scope and
budget; the durability protocol preserves its bounded recovery invariants; and
completion is backed by artifact and journal evidence.

These claims are deliberately local to the implemented fixtures, generated
cases, declared bounds, and recorded host. They do not generalize themselves.

## Rejected claims

The current evidence does not show improved LLM task understanding,
categorical superiority over conventional typed IR, an effectful source-level
language, hostile-code isolation inside BEAM, production scale, live-model
reliability, exactly-once external effects, portable delegation, or formal
proof. Property tests and one deterministic demo cannot establish those
claims.

## Next decision boundary

The next and only authorized question is:

> Can user-authored effectful A-Lang source improve task-specification fidelity
> over a conventional typed notation while compiling through the same BEAM
> runtime enforcement path?

Acceptance tasks must originate in source syntax rather than manually
constructed IR. The source must cover the current model, workspace, child-task,
and completion vocabulary; derive manifests statically; and produce local
diagnostics. A matched evaluation must hold runtime enforcement constant,
compare multiple task families against a conventional typed notation, and
measure task-specification fidelity across at least two declared model
families. Human authoring or review advantages may be claimed only after a
human study.

The next prototype must retain all current broker, durability, adversarial,
fault, and completion gates. Promotion requires a fidelity benefit without a
weaker runtime boundary.

The authorized work is specified by the
[effectful source fidelity plan](../../60-planning/02-effectful-source-fidelity/README.md),
which freezes the paired A-Lang/typed-JSON corpus, two hosted model families,
deterministic scoring, safety vetoes, and promote/replace/stop threshold before
implementation or live evaluation.

## Frozen scope

Until that decision is made, do not add general recursion, polymorphism,
parallel composition, distribution, portable delegation, more effect families,
package management, self-hosting, or user-visible categorical notation. These
features would enlarge the system while leaving the central language-value
question unresolved.

## Consequences

The next implementation effort should concentrate on the missing surface-to-IR
path and its evaluation, not on runtime breadth. BEAM, the broker, durability,
and verification remain controlled infrastructure. A negative source-fidelity
result should stop language expansion or replace the novel surface with the
best-performing conventional typed notation while preserving independently
valuable runtime enforcement.

The active research inquiries remain open because this prototype narrows their
questions; it does not resolve general LLM-agent, categorical, or BEAM
production claims. They will be reconciled with this decision in the final
Phase 8 status ledger.
